# 04_PRODUCT_UX_ACCESSIBILITY_REQUIREMENTS

## 제품 원칙

1. 한 화면에 한 판단만 보이게 한다.
2. 긴 문장보다 짧은 행동 문장이 우선이다.
3. 사용자가 기억하지 않아도 되게 만든다.
4. 설명은 쉬워야 하지만 유치하면 안 된다.
5. 선택지가 많아 보여도 실제 기본 화면은 단순해야 한다.

## 핵심 UI 모드

### Live HUD
- 원본 화면 위 최소 개입
- 현재 재난 유형
- 현재 세그먼트 제목
- Shadow 보기 버튼
- Panic 버튼

### Shadow Player
- 4초 지연 재생
- 일시정지/되감기/다시보기 가능
- 세그먼트 카드 표시
- 트랙 선택 가능

### Panic Mode
- 한눈에 핵심 3줄
- 지금 해야 할 것
- 금지 행동
- 신고 문장

## 트랙 정의

- basic: 장면 설명
- easy: 쉬운말 재설명
- action: 지금 해야 할 한 가지
- reason: 이유
- caregiver: 보호자/지원인 시점
- report: 신고/도움요청 문장

## 글쓰기 규칙

### 공통
- 존댓말
- 한 문장 20자~45자 권장
- 괄호 남발 금지
- 전문어 쓰면 바로 풀어쓰기
- 같은 의미 반복 금지

### action
- 명령문
- 한 행동만
- 18자 이내를 목표로

예시:
- 몸을 낮추고 계단으로 이동하세요
- 탁자 아래로 들어가 몸을 보호하세요

### reason
- 왜를 1문장으로
- 공포 조장 금지
- 추상 설명 금지

예시:
- 연기는 위로 올라가서 몸을 낮추는 것이 더 안전합니다

### report
- 그대로 읽을 수 있는 문장으로 작성

예시:
- 119에 “여기 OO건물 3층, 연기가 많아요”라고 말하세요

## 인터랙션 원칙

- 기본값은 `easy + action`이 가장 잘 보이게
- 사용자는 탭/버튼으로 다른 트랙을 열어볼 수 있게
- 평가 받는 느낌보다 도와주는 느낌을 줘야 함
- “정답/오답”보다 “다시 보기/다시 듣기”가 앞에 와야 함

## UI 구성 규칙

- 카드 1개당 정보 4줄 이하
- 강조 색은 2개 이하
- 화면 흔들림 애니메이션 금지
- 글자 크기 대비를 크게
- 오버레이는 화면을 가리지 않게 가장자리 정렬 우선

## Codex에게 바로 맡길 일

- Live HUD 와 Shadow Player 와이어프레임 구현
- 트랙 탭 UI 구현
- Panic Mode UI 구현
- 세그먼트 카드 템플릿 구현
- 글자 크기/간격/색 대비 토큰 정의
